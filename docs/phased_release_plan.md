# 移動距離計測アプリ（トラベルメーター） 段階リリース計画書

## 1. 概要・方針

本計画書は、「移動距離計測アプリ（トラベルメーター）」の要件定義書に基づき、開発を段階的に進めるためのリリース計画です。

### 開発方針
1. **各フェーズでの動作可能状態（Working Software）の維持**: 
   各フェーズ完了時点で必ず「ビルド可能」「アプリ起動可能」「動作確認可能」な状態とします。
2. **Gemini無料枠・トークン制限への配慮**: 
   一度に大量のコードを生成・変更するとトークン上限や精度低下のリスクがあるため、1回の対話・セッションで無理なく実装・テストできる適切な単位に機能を分割します。
3. **ボトムアップ＆価値検証**: 
   UIモックから開始し、コア機能（位置情報計測）、データ集計、履歴・統計、設定へと段階的に拡張します。

---

## 2. 段階リリース計画（全5フェーズ）

```
[Phase 1] 基盤構築 & ダッシュボードUI（モック動作）
   └─> [Phase 2] リアルタイム位置情報計測 & フォアグラウンドサービス
          └─> [Phase 3] 時間別集計ロジック & ホーム画面リアルデータ連携
                 └─> [Phase 4] 履歴・詳細画面（カレンダー & サマリー）
                        └─> [Phase 5] 設定機能 & 全体仕上げ・最適化
```

---

### Phase 1: アプリ基盤・ダッシュボード画面UI構築（モック動作）

- **目的**: アプリの基盤構造（ライブラリ追加、DB定義、基本ViewModel）を整理し、ダッシュボード画面のUIをモックデータで動作確認できる状態にする。
- **実装スコープ**:
  - Gradle依存関係のセットアップ（Room, Fused Location Provider, Navigation, DataStore, Coroutinesなど）
  - Room EntityおよびDAOの初期定義（`LocationLogEntity`, `HourlySummaryEntity`）
  - Material 3テーマ・カラーの整理
  - ホーム画面（ダッシュボード）UIの実装
    - 総移動距離表示カード
    - 目標達成プログレスリング
    - 時間単位移動距離グラフ（モックデータでの表示）
    - 計測開始/停止ボタンUI
  - ダッシュボード用ViewModelとモックデータソースの構築
- **動作確認基準**:
  - プロジェクトが正常にビルド可能。
  - アプリ起動後、ホーム画面にデザイン通りの総移動距離、プログレスリング、時間別グラフがモック表示される。
  - 「開始/停止」ボタンタップでUIのステート（計測中/停止中）が切り替わることを確認。

---

### Phase 2: リアルタイム位置情報計測 & フォアグラウンドサービス

- **目的**: 実際のGPS位置情報を取得し、バックグラウンド・フォアグラウンドで移動距離をリアルタイム計測・保存するコアエンジンを実装する。
- **実装スコープ**:
  - AndroidManifestへの権限（`ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`等）追加
  - 位置情報パーミッション要求フロー（Compose runtime permission / ActivityResultLauncher）の実装
  - Fused Location Providerを利用した位置情報取得ロジック (`LocationRepository`)
  - 位置情報間距離計算 (Haversine formula または `Location.distanceBetween`)
  - Foreground Service (`TrackingService`) と常時通知 (Notification) の実装
  - 取得した位置ログのRoom DB (`LocationLogEntity`) への保存
- **動作確認基準**:
  - パーミッションダイアログが正常に表示・許可できる。
  - 「計測開始」タップで通知が表示され、端末を移動させるとリアルタイムで総移動距離が更新される。
  - アプリをバックグラウンドに移動・画面消灯しても、通知領域で距離カウントが継続する。

---

### Phase 3: 時間別集計ロジック & ホーム画面のリアルデータ連携

- **目的**: 取得した位置ログから「1時間ごとの移動距離」を自動計算・集計し、ダッシュボード画面のグラフやタイムラインへ実データを連携する。
- **実装スコープ**:
  - 毎時集計処理ロジックの実装（`HourlySummaryEntity`の作成・更新）
  - 静止判定/ノイズフィルタリング（一定速度以下や微小移動の除去）
  - ダッシュボードViewModelとRoom DBのリアルタイムデータ連携（Flow / StateFlow）
  - 24時間バーチャート / タイムラインUIの実データ対応
  - 当日の最も移動が多かった時間帯（ピーク時間）のハイライト表示
- **動作確認基準**:
  - 移動計測結果が1時間ごとのバケットに分類されてDBに集計保存される。
  - ホーム画面の時間別グラフが、実際の移動時間帯に応じて動的にバーの高さや値を表示する。
  - ピーク時間帯のハイライトが正しく更新される。

---

### Phase 4: 履歴・詳細画面（カレンダー & 日別・週別・月別サマリー）

- **目的**: 過去の移動データを振り返ることができる履歴画面・カレンダー画面を実装する。
- **実装スコープ**:
  - 画面間ナビゲーションの追加（ホーム画面 ↔ 履歴画面 ↔ 設定画面）
  - 日付選択カレンダーUIの実装
  - 選択した日の時間別詳細リスト（0:00〜23:00の内訳）
  - 日別・週別・月別のサマリー集計機能（総移動距離、平均距離、最長移動日）
  - カレンダー上への移動実績マーク表示
- **動作確認基準**:
  - ホーム画面から履歴画面への遷移ができる。
  - カレンダーで過去の日付を選択すると、その日の時間別移動距離一覧および集計値が表示される。
  - データが存在しない日・データが存在する日の表示切替が正しく動作する。

---

### Phase 5: 設定機能 & バッテリー最適化・全体仕上げ

- **目的**: 目標設定、権限・省電力ガイド、設定画面を完成させ、アプリ全体の品質を向上させる。
- **実装スコープ**:
  - Jetpack DataStoreによる目標移動距離・アプリ設定の永続化
  - 設定画面UI（1日の目標距離設定、通知オン/オフ、省電力モード設定）
  - バッテリー最適化ダイアログ（バックグラウンド動作を制限しないガイド）の導入
  - ホーム画面の目標達成プログレスリングと設定値の連動
  - ダークモード対応・Material 3スタイルの最終調整
  - エラーハンドリング・位置情報オフ時の案内ダイアログ
- **動作確認基準**:
  - 設定画面で目標距離（例: 8.0 km）を変更すると、ホーム画面の達成率プログレスリングに即座に反映される。
  - GPSが無効になっている場合に適切な警告が表示される。
  - アプリ全体でビルドエラーや警告、クラッシュが発生しない。

## 3. フェーズ別サマリー表

| フェーズ | 主要機能 | 主な成果物 | 動作確認ポイント |
| :--- | :--- | :--- | :--- |
| **Phase 1** | UIモック＆データ基盤 | DBエンティティ, ViewModel, ダッシュボードUI | モックデータでホーム画面表示、ボタン切替 |
| **Phase 2** | 位置情報計測・Foreground Service | Service, LocationRepository, パーミッション処理 | 実機/エミュレータでの移動距離リアルタイム加算・通知表示 |
| **Phase 3** | 時間別集計・実データグラフ連携 | 時間集計ロジック, DB連携Flow, 時間別グラフUI | 実際の移動が1時間ごとのグラフ・ピーク表示に反映 |
| **Phase 4** | 履歴画面・カレンダー表示 | 履歴UI, カレンダー, 週別/月別サマリー | 過去日付の選択と時間別詳細・統計表示 |
| **Phase 5** | 設定・目標管理・仕上げ | 設定画面, DataStore, バッテリーガイド, UIブラッシュアップ | 目標距離変更の即時反映, エラーガイド, 完成版ビルド |

## 4. 各フェーズ開発時の推奨プロンプト指示例

Geminiに実装を依頼する際は、以下のようにフェーズを指定して依頼することで、トークン制限内で確実なコード生成が行えます。

- **Phase 1依頼例**:
  > 「段階リリース計画の Phase 1 を実装してください。Gradleに必要な依存関係を追加し、Roomのエンティティ定義とモックデータで動くダッシュボード画面UI（プログレスリング、時間別グラフモック）を作成してください。ビルド可能で起動できる状態でお願いします。」

- **Phase 2依頼例**:
  > 「段階リリース計画の Phase 2 を実装してください。Fused Location ProviderとForeground Serviceを使って、バックグラウンドでも移動距離を計測・更新する機能を実装してください。」
